collect real offers, structure them, match them against your own skills, help you

**Why `structured_offers.json` and `matches_all_local.json` never get committed:**
France Travail's data is official government open data, licensed for reuse — but if
you add the optional second source (jobspy), that's scraped from platforms whose
Terms of Service prohibit redistribution, which is worse than the scraping itself.
Rather than track which files are safe depending on what you did, every intermediate
file that could contain mixed-source content stays local-only; the only thing ever
committed is `docs/data/matches.json`, already filtered to publishable sources by
`match_offers.py` itself.

### Data and tools — what's real and verified

- **France Travail "Offres d'emploi v2" API** — France's official employment agency,
  300,000+ real-time offers, free (registration required, no payment). Confirmed by
  real testing: **"stage" is not a filterable contract type in this API's own
  taxonomy at all** — a "stage" is governed by a school *convention de stage*, not an
  employment contract, so it isn't in this jobs API's contract-type list. The pipeline
  searches by keyword instead, and only asks the AI model to interpret the free-text
  description for things the API doesn't already give reliably (title, company,
  location, an accessibility flag, an apprenticeship flag are all structured fields
  already). This is the CM5 principle directly: use AI where it adds value, not as a
  substitute for structured data you already have.
- **Ollama, a local open-weight model (tested with `qwen3:8b`)** — free, no account,
  no billing risk. Verified on real postings: correctly separates actual tools/skills
  from task descriptions, correctly returns `null` for things not stated rather than
  inventing them. Extraction: ~20-30s/offer. CV drafting: ~30-90s/offer — noticeably
  slower, which is why `draft_cv.py` only runs on your top few matches.
- **`python-jobspy` (optional second source)** — scrapes Indeed, LinkedIn,
  ZipRecruiter, Google Jobs. Unlike every other source in this course, this is **not**
  an official API its providers permit reusing — a different risk category, covered
  in full where it comes up below.

3. Confirm it's reachable:
   ```
   curl --noproxy '*' http://127.0.0.1:11434/api/version
   ```
   should return a version string, not an HTML proxy page. **The `--noproxy '*'`
   matters on some networks** (a plain `curl` can get silently intercepted by an
   institutional proxy, which looks like Ollama is broken when it isn't). Every
   Python script below already handles this for you
   (`proxies={"http": None, "https": None}`) — this is the one place you're issuing
   the request directly, so it's the one place you need the flag by hand.

### Step 7 — Add the offer-fetching script (`scripts/fetch_offers.py`)

```python
import json, os, sys, time
import requests

# France Travail "Offres d'emploi v2" API -- OAuth2 client_credentials flow.
# The auth flow below (token endpoint, client_credentials, scope) was confirmed
# working against a real account. The typeContrat filter went through two
# failed real attempts: first a hardcoded guess ("STA"), rejected by the API;
# then a lookup against the API's own referentiel/typesContrats endpoint,
# which DID work but returned the real, authoritative list of contract-type
# codes -- CCE, CDD, CDI, DDI, DIN, FRA, LIB, MIS, REP, SAI, TTI, DDT -- and
# none of them is "stage". That's not a bug to route around; it reflects a
# real legal distinction in France: a "stage" is governed by a school
# "convention de stage", not an employment contract, so it may not live in
# this employment-offers API's contract-type taxonomy at all.
#
# Rather than guess a third field name, this version does not depend on any
# exact categorical match existing. It searches by keyword instead (motsCles
# does full-text matching over title and description, and real internship
# postings reliably say "stage" or "stagiaire" in their text) and treats a
# contract-type filter as optional, best-effort enrichment: it tries to find
# a "stage"-labeled code in the referentiel and applies it only if one
# exists, logging clearly either way instead of crashing.

TOKEN_URL = "https://entreprise.francetravail.fr/connexion/oauth2/access_token?realm=/partenaire"
SEARCH_URL = "https://api.francetravail.io/partenaire/offresdemploi/v2/offres/search"
REFERENTIEL_CONTRATS_URL = "https://api.francetravail.io/partenaire/offresdemploi/v2/referentiel/typesContrats"

CLIENT_ID = os.environ["FRANCETRAVAIL_CLIENT_ID"]
CLIENT_SECRET = os.environ["FRANCETRAVAIL_CLIENT_SECRET"]
SCOPE = "api_offresdemploiv2 o2dsoffre"

# Edit this to your own search. Two defaults worth calling out:
# - motsCles targets computer engineering ("informatique"), not data specifically
#   -- ENSIM students are computer engineers generally, and "data stage" alone
#   was too narrow (it returned zero results on a real run: HTTP 204, no
#   offers matched that exact combination for one city).
# - No commune/distance filter is set, so the search is nationwide by
#   default -- this API's own docs list both as optional location filters, and
#   omitting an optional filter should broaden rather than restrict results
#   (standard REST search semantics), though that specific behavior hasn't
#   been verified against this API in a real run yet. If you want to restrict
#   to a region instead, add back "commune": "<INSEE code>" and "distance":
#   "<km>" -- see Step 10 for what to check if that changes the result count
#   unexpectedly.
SEARCH_PARAMS = {
    "motsCles": "stage informatique",
    "sort": "1",                 # sort by date, most recent first
    "range": "0-49",             # first 50 results; see note below for more
}

def get_access_token(retries=4, backoff=5):
    last_error = None
    for attempt in range(1, retries + 1):
        try:
            resp = requests.post(
                TOKEN_URL,
                data={
                    "grant_type": "client_credentials",
                    "client_id": CLIENT_ID,
                    "client_secret": CLIENT_SECRET,
                    "scope": SCOPE,
                },
                headers={"Content-Type": "application/x-www-form-urlencoded"},
                timeout=(10, 20),
            )
            resp.raise_for_status()
            return resp.json()["access_token"]
        except requests.exceptions.RequestException as e:
            last_error = e
            print(f"  token request attempt {attempt}/{retries} failed: {e}")
            if hasattr(e, "response") and e.response is not None:
                print(f"  response body: {e.response.text[:500]}")
            if attempt < retries:
                time.sleep(backoff * attempt)
    raise RuntimeError(f"Could not obtain access token after {retries} attempts") from last_error

def try_resolve_contract_type_code(token, label_substring="stage"):
    """Best-effort only: look up a typeContrat code matching label_substring
    from France Travail's own referentiel endpoint. Returns None (never
    raises) if the endpoint is unreachable or no match exists -- confirmed by
    real testing that "stage" has no match in this taxonomy at all, which is
    an honest fact about the data (see the module docstring above), not a
    failure to fix. main() falls back to keyword-only search when this
    returns None."""
    try:
        resp = requests.get(
            REFERENTIEL_CONTRATS_URL,
            headers={"Authorization": f"Bearer {token}"},
            timeout=(10, 20),
        )
        resp.raise_for_status()
        all_types = resp.json()
        print("Available contract types:", json.dumps(all_types, ensure_ascii=False))
        for t in all_types:
            if label_substring.lower() in t.get("libelle", "").lower():
                print(f"Resolved '{label_substring}' -> code '{t['code']}' ({t['libelle']})")
                return t["code"]
        print(f"No contract type matches '{label_substring}' -- proceeding with keyword search only "
              f"(this is expected: 'stage' is not part of this API's contract-type taxonomy).")
        return None
    except requests.exceptions.RequestException as e:
        print(f"Could not fetch contract-type referentiel ({e}) -- proceeding with keyword search only.")
        return None

def search_offers(token, retries=4, backoff=5):
    last_error = None
    for attempt in range(1, retries + 1):
        try:
            resp = requests.get(
                SEARCH_URL,
                params=SEARCH_PARAMS,
                headers={"Authorization": f"Bearer {token}"},
                timeout=(10, 30),
            )
            print(f"  search attempt {attempt}/{retries}: HTTP {resp.status_code}, "
                  f"body starts with: {resp.text[:200]!r}")
            # This API returns 206 (Partial Content) with a Content-Range header
            # on a normal successful paginated response, and 204 (No Content,
            # empty body) when the search matched zero offers -- both are
            # success, not errors, and 204 must be handled before trying to
            # parse a body that doesn't exist. Anything else is a real error.
            if resp.status_code == 204:
                return {"resultats": []}
            if resp.status_code not in (200, 206):
                resp.raise_for_status()
            return resp.json()
        except requests.exceptions.RequestException as e:
            last_error = e
            print(f"  search attempt {attempt}/{retries} failed: {e}")
            if hasattr(e, "response") and e.response is not None:
                print(f"  response body: {e.response.text[:500]}")
            if attempt < retries:
                time.sleep(backoff * attempt)
    raise RuntimeError(f"Could not search offers after {retries} attempts") from last_error

def main():
    print("Requesting access token...")
    token = get_access_token()

    print("Checking whether a 'stage' contract type code exists...")
    code = try_resolve_contract_type_code(token, "stage")
    if code:
        SEARCH_PARAMS["typeContrat"] = code

    print("Got token, searching offers...")
    data = search_offers(token)
    offers = data.get("resultats", [])
    print(f"Found {len(offers)} offers")

    os.makedirs("data/offers", exist_ok=True)
    with open("data/offers/raw_offers.json", "w") as f:
        json.dump({"fetched_at": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime()),
                   "search_params": SEARCH_PARAMS, "offers": offers}, f, indent=2, ensure_ascii=False)
    print("Wrote data/offers/raw_offers.json")
    if offers:
        print("First offer preview:", json.dumps(offers[0], ensure_ascii=False, indent=2)[:800])

if __name__ == "__main__":
    main()
```

**Note on `range`:** this API caps each request at 150 results, max ~1,150 per search
by paging. Fifty is plenty for a personal search.

### Step 11b — Optional: add a second local data source (`scripts/fetch_offers_jobspy.py`)

**Read this before running any code — it genuinely changes this project's risk
profile.** France Travail's API (Steps 6-10) is an official government source its
provider explicitly permits reusing. `python-jobspy` is different: it scrapes
Indeed, LinkedIn, ZipRecruiter, and Google Jobs, and each platform's Terms of
Service prohibits automated scraping.

- **This is real legal exposure, not a grey area.** *hiQ Labs v. LinkedIn* protected
  scraping *public* data from US CFAA claims, but *Meta v. Bright Data* (2024)
  confirmed ToS violation is still real breach-of-contract exposure, independent of
  that question. LinkedIn specifically is the highest-exposure choice here — it's the
  party that brought the *hiQ* case, i.e. a platform known to actively litigate this.
- **It's also less reliable.** jobspy works via reverse-engineered, unofficial
  endpoints; LinkedIn changed its page structure multiple times in 2025, each time
  temporarily breaking jobspy's scraper for it — a structurally different failure
  mode than an official, versioned API.
- **Publishing scraped results is a separate, worse problem than scraping them.**
  Redistributing copyrighted third-party postings on a public GitHub Pages site is a
  bigger exposure than a single personal, on-demand fetch — which is why the merge
  step and `match_offers.py` treat jobspy-sourced offers as **never publishable**,
  automatically.

Given this, the script makes three deliberate risk-reducing choices — and you can
skip this entirely, the France Travail pipeline already works on its own:

1. **Runs locally only, on demand — never via GitHub Actions.**
2. **Defaults to Indeed and ZipRecruiter, not LinkedIn or Google** — dropping
   specifically the highest-enforcement-risk site and the SERP-scraping site, while
   keeping the sites that actually returned data in real testing.
3. **Writes to a gitignored file.**

Install first: `pip install -U python-jobspy` (needs Python 3.10+).

```python
import json, os, time
import pandas as pd
from jobspy import scrape_jobs

# See the caveats above before running this. Summary: jobspy scrapes commercial
# platforms whose ToS prohibits it -- a different risk category than every other
# source in this course. Runs local-only, on demand, never in GitHub Actions.

SITES = ["indeed", "zip_recruiter"]  # deliberately excludes linkedin, google -- see Step 11b
SEARCH_TERM = "stage informatique"
LOCATION = "France"
RESULTS_WANTED = 30
HOURS_OLD = 336  # 14 days -- this runs manually/occasionally, not on a schedule

def safe(row, key, default=None):
    # pandas NaN is truthy in Python (bool(float('nan')) is True), so a plain
    # `row.get(key) or default` silently returns the NaN itself instead of the
    # default -- confirmed on real scraped data, where ~half the rows had NaN
    # in optional fields like `description`. pd.notna() is the actual check needed.
    v = row.get(key)
    return v if pd.notna(v) else default

def main():
    print(f"Scraping {SITES} for '{SEARCH_TERM}' in {LOCATION}...")
    jobs = scrape_jobs(
        site_name=SITES,
        search_term=SEARCH_TERM,
        location=LOCATION,
        results_wanted=RESULTS_WANTED,
        hours_old=HOURS_OLD,
        country_indeed=LOCATION,
    )
    print(f"Found {len(jobs)} raw results")

    # jobspy normalizes job_type across sites into its own vocabulary that includes
    # "internship" directly -- confirmed on a real run of this exact logic
    # (2026-09-08): a genuine French "Stage" posting on Indeed came back with
    # job_type == "internship". More precise than France Travail's contract-type
    # taxonomy, which has no internship category at all (see fetch_offers.py).
    interns = jobs[jobs["job_type"].fillna("").str.contains("internship", case=False)]
    print(f"{len(interns)} of those are tagged job_type=internship")

    offers = []
    for _, row in interns.iterrows():
        offers.append({
            "id": f"jobspy_{safe(row, 'id')}",
            "source": safe(row, "site"),
            "title": safe(row, "title"),
            "company": safe(row, "company"),
            "location": safe(row, "location"),
            "description": safe(row, "description", ""),
            "url": safe(row, "job_url"),
            "date_posted": str(safe(row, "date_posted")) if safe(row, "date_posted") else None,
        })

    os.makedirs("data/offers", exist_ok=True)
    with open("data/offers/jobspy_offers.json", "w") as f:
        json.dump({"fetched_at": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime()),
                   "offers": offers}, f, indent=2, ensure_ascii=False)
    print(f"Wrote data/offers/jobspy_offers.json ({len(offers)} offers) -- gitignored, local only")

if __name__ == "__main__":
    main()
```

**Checkpoint:** `data/offers/jobspy_offers.json` exists with one entry per
internship-tagged result, and does **not** appear in `git status` as stageable.

### Step 11c — Optional: merge sources into one common format (`scripts/merge_offer_sources.py`)

The real point of this step, whether or not you did 11b: this course's pipelines have
always ended acquisition with **structuring** — normalizing multiple real sources
into one common schema, not just picking whichever is easiest, is the actual
data-engineering skill here.

```python
import json, os

RAW_FT_PATH = "data/offers/raw_offers.json"
JOBSPY_PATH = "data/offers/jobspy_offers.json"
MERGED_PATH = "data/offers/merged_offers.json"

def normalize_france_travail(raw_offers):
    # France Travail's raw fields, confirmed by extract_offers.py's own field
    # access below -- this project's most-tested France Travail assumptions.
    # url/date_posted are left None deliberately: no confirmed real field name
    # for either exists yet in this manual (Step 10 hadn't returned real, non-empty
    # results when this was written) -- once your own Step 10 run has real offers,
    # inspect one in data/offers/raw_offers.json yourself and add the real field
    # name here if you want working links, rather than this guessing a third time.
    normalized = []
    for o in raw_offers:
        normalized.append({
            "id": f"ft_{o['id']}",
            "source": "france_travail",
            "title": o.get("intitule"),
            "company": (o.get("entreprise") or {}).get("nom"),
            "location": (o.get("lieuTravail") or {}).get("libelle"),
            "description": o.get("description", ""),
            "url": None,
            "date_posted": None,
            "is_apprenticeship": o.get("alternance", False),
            "accessible_disability": o.get("accessibleTH", False),
            "publishable": True,  # official open government data -- safe to publish
        })
    return normalized

def load_jobspy():
    if not os.path.exists(JOBSPY_PATH):
        print(f"{JOBSPY_PATH} not found -- skipping (fine if you didn't do Step 11b).")
        return []
    with open(JOBSPY_PATH) as f:
        data = json.load(f)
    return [
        {**o, "is_apprenticeship": False, "accessible_disability": False,
         "publishable": False}  # scraped content -- never published, see Step 11b
        for o in data["offers"]
    ]

def main():
    with open(RAW_FT_PATH) as f:
        ft_raw = json.load(f)
    ft_offers = normalize_france_travail(ft_raw["offers"])
    jobspy_offers = load_jobspy()

    merged = ft_offers + jobspy_offers
    print(f"Merged {len(ft_offers)} France Travail + {len(jobspy_offers)} jobspy = {len(merged)} total")

    os.makedirs("data/offers", exist_ok=True)
    with open(MERGED_PATH, "w") as f:
        json.dump({"offers": merged}, f, indent=2, ensure_ascii=False)
    print(f"Wrote {MERGED_PATH} ({len(merged)} offers) -- gitignored, local only")

if __name__ == "__main__":
    main()
```

The `"publishable"` flag carried on every offer is what `match_offers.py` uses to
keep scraped content out of the committed dashboard automatically.

**Checkpoint:** `data/offers/merged_offers.json` exists. If you skipped Step 11b, it

## Stage 2: Structuring — where AI earns its place (CM5)

### Step 12 — Add the local extraction script (`scripts/extract_offers.py`)

Run locally (Step 3's machine), not via GitHub Actions — heavier compute than a free
Actions runner (no GPU) would handle well, and running it yourself means you're
present when the AI output appears, per this course's human-in-the-loop principle.

```python
import json, os, time
import requests

OLLAMA_URL = "http://127.0.0.1:11434/api/generate"
MODEL = "qwen3:8b"

PROMPT_TEMPLATE = """Extract ONLY these things from this job/internship description text
(it may be in French or English).
Return ONLY valid JSON with keys:
- required_skills: array of concrete named tools/technologies/hard skills mentioned (e.g. "Python", "Power BI") -- do not include generic soft skills or the job title
- responsibilities: array of the actual tasks/missions described
- experience_required: a short string quoting the explicit experience requirement stated in the text (e.g. "2 years", "no experience required", "Bac+5", "enrolled in a Master's program"), or null if the text does not explicitly state one. Do NOT infer this from the job title, from words like "Senior"/"Lead" in the title, or from general seniority tone -- only from an actual requirement sentence in the text.
- compensation_mentioned: a short verbatim quote of any salary/compensation/gratification FIGURE explicitly stated in the text (e.g. "75-90k EUR package", "600 euros/mois"), or null if no concrete number is stated anywhere in the text. Read the ENTIRE text, including the end, before concluding there is none.

Do not extract title, company, or location -- those come from elsewhere and are not in this text.
No explanation, just the JSON object.

TEXT:
{text}
"""

def call_ollama(prompt, retries=3, backoff=5):
    last_error = None
    for attempt in range(1, retries + 1):
        try:
            resp = requests.post(
                OLLAMA_URL,
                proxies={"http": None, "https": None},
                json={"model": MODEL, "prompt": prompt, "format": "json", "stream": False},
                timeout=(10, 120),
            )
            resp.raise_for_status()
            return json.loads(resp.json()["response"])
        except Exception as e:
            last_error = e
            print(f"  Ollama call attempt {attempt}/{retries} failed: {e}")
            if attempt < retries:
                time.sleep(backoff)
    raise RuntimeError(f"Ollama unreachable or model not available after {retries} attempts") from last_error

def main():
    # Reads the merged, common-schema file (Step 11c), not raw_offers.json directly
    # -- this script no longer needs to know which source an offer came from, since
    # merge_offer_sources.py already normalized every source to the same field names.
    with open("data/offers/merged_offers.json") as f:
        merged = json.load(f)

    structured = []
    for offer in merged["offers"]:
        print(f"Extracting offer {offer['id']} ({offer['source']}): {offer['title']}...")
        extracted = call_ollama(PROMPT_TEMPLATE.format(text=offer.get("description", "")))
        structured.append({
            "id": offer["id"],
            "source": offer["source"],
            "title": offer["title"],
            "company": offer.get("company"),
            "location": offer.get("location"),
            "is_apprenticeship": offer.get("is_apprenticeship", False),
            "accessible_disability": offer.get("accessible_disability", False),
            "publishable": offer.get("publishable", False),
            "required_skills": extracted.get("required_skills", []),
            "responsibilities": extracted.get("responsibilities", []),
            "experience_required": extracted.get("experience_required"),
            "compensation_mentioned": extracted.get("compensation_mentioned"),
        })

    os.makedirs("data/offers", exist_ok=True)
    with open("data/offers/structured_offers.json", "w") as f:
        json.dump({"generated_at": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime()),
                   "offers": structured}, f, indent=2, ensure_ascii=False)
    print(f"Wrote data/offers/structured_offers.json ({len(structured)} offers) -- gitignored, local only")

if __name__ == "__main__":
    main()
```

Tested on realistic postings: correctly separates tools (`"Python"`, `"Power BI"`)
from tasks (`"construction de tableaux de bord Power BI"`), and correctly returns an
empty/minimal result rather than inventing content for a vague posting.
`experience_required` and `compensation_mentioned` were tested specifically for the
failure mode that matters most with an LLM — **hallucinating a number that isn't
actually stated** — against real cases including a compensation figure buried at the
very end of a long posting (correctly found) and a posting with no figure anywhere
(correctly returned `null`, not invented).

**A blunt finding you need before you design a KPI around this field: real data
shows compensation is rarely stated at all.** Checked against 531 real postings for
this course's own search terms: 0 had any structured salary field populated, and
only ~35 (~6.5%) even mentioned a concrete figure anywhere in the free text. Don't
design your dashboard around a salary-range chart — there usually isn't enough real
data to make one honestly. That's a fact about the internship market worth reporting
in your write-up, not a gap in this pipeline.

**Checkpoint:** `data/offers/structured_offers.json` exists with one entry per
fetched offer, each with populated `required_skills` and `responsibilities` arrays.

### Your task: define the match KPI

`score_offer(profile, required_skills)` is called once per offer. Its output is what
every downstream step — the ranking, the top-gaps/top-matched-skills summaries,
`draft_cv.py`'s evidence selection, and your own dashboard — is built on. Per CM2:
a KPI is a construct you choose, not a neutral fact, and this is the real version of
that exercise, not a toy one — your actual search gets ranked by whatever you decide
here.

**Inputs:**

| Name | Shape | Notes |
|---|---|---|
| `profile` | `dict`: skill name (str) → `{"level": int 1-5, "evidence": str}` | Your own `my_skills.csv`, already loaded by `load_profile()`. |
| `required_skills` | `list[str]` | Skills the AI extracted for *this one offer* (Step 12). May be empty. |

**Required output — a `dict` with at least these four keys:**

| Key | Shape | Contract |
|---|---|---|
| `"score"` | number | Used to rank offers (`results.sort(key=lambda r: r["score"], reverse=True)`). Higher must mean a better match — beyond that, the definition is yours. |
| `"coverage"` | number | "How much of this offer do I cover?" Doesn't have to be a fraction of exactly `[0, 1]`, but should be something you can defend as meaningful, since `draft_cv.py` filters candidates by `coverage >= MIN_COVERAGE`. |
| `"matched"` | `list[str]` | Skills from `required_skills` you consider matched against your profile. `draft_cv.py` uses this list directly to decide what evidence to quote in a cover letter — don't include a skill here you can't actually back up. |
| `"gaps"` | `list[str]` | Skills from `required_skills` you consider missing. Feeds `build_output`'s `top_skill_gaps` summary — a real, actionable "what should I learn next" signal if this is right. |

**A real design question you have to answer, not a hypothetical:** does `"matched"`
require an exact string match between `required_skills` and your profile's keys? A
real, confirmed finding from this course's own testing: the same skill can come back
from the AI extraction step with inconsistent capitalization across different calls
(`"Computer vision"` in one offer, `"computer vision"` in another) — a naive
exact-match implementation will silently undercount real matches for exactly this
reason, every time it happens. Deciding how to handle this (normalize case before
comparing? something else?) is part of the actual KPI design here, not an edge case
you can ignore.

Once `score_offer` returns something real, `main()`'s printed ranking is your first
sanity check — do the top-ranked offers actually look like a better match than the
bottom ones, by eye, against a couple of real offers you recognize?

**Checkpoint:** `data/offers/matches_all_local.json` exists with every offer scored,
and `docs/data/matches.json` exists with only publishable ones.

```python
import csv, json, os, time
import requests

OLLAMA_URL = "http://127.0.0.1:11434/api/generate"
MODEL = "qwen3:8b"
TOP_N = 3
MIN_COVERAGE = 0.3

d'accroche (3-4 phrases) d'une lettre de motivation en francais, pour l'offre suivante, en
mettant en avant UNIQUEMENT les competences du candidat qui correspondent reellement a l'offre
(n'invente aucune competence ou experience non listee ci-dessous).

Offre: {title} chez {company}
Missions: {responsibilities}
Competences requises correspondantes chez le candidat: {matched_skills}
Preuves concretes du candidat: {evidence}

Ne pas hallucinerd'experience professionnelle non mentionnee. Style: direct, concret, pas de
formules creuses.
"""

def load_profile(path="data/profile/my_skills.csv"):
    profile = {}
    with open(path) as f:
        for row in csv.DictReader(f):
            profile[row["skill"]] = row["evidence"]
    return profile

def call_ollama(prompt, retries=3, backoff=5):
    last_error = None
    for attempt in range(1, retries + 1):
        try:
            resp = requests.post(
                OLLAMA_URL,
                proxies={"http": None, "https": None},
                json={"model": MODEL, "prompt": prompt, "stream": False},
                timeout=(10, 180),
            )
            resp.raise_for_status()
            return resp.json()["response"].strip()
        except Exception as e:
            last_error = e
            print(f"  Ollama call attempt {attempt}/{retries} failed: {e}")
            if attempt < retries:
                time.sleep(backoff)
    raise RuntimeError(f"Ollama unreachable after {retries} attempts") from last_error

def main():
    profile = load_profile()
    # Reads matches_all_local.json (every source), not docs/data/matches.json --
    # drafting a private cover letter from a jobspy-sourced offer is exactly the
    # personal, non-publishing use Step 11b's caveat allows; only *publishing* the
    # scraped listing itself is what's restricted, and that restriction is already
    # enforced upstream in match_offers.py, not here.
    with open("data/offers/matches_all_local.json") as f:
        data = json.load(f)

    candidates = [o for o in data["offers"] if o["coverage"] >= MIN_COVERAGE][:TOP_N]
    print(f"Drafting opening paragraphs for {len(candidates)} of {data['n_offers']} offers "
          f"(coverage >= {MIN_COVERAGE:.0%}, top {TOP_N})")

    os.makedirs("output/cv_drafts", exist_ok=True)
    for offer in candidates:
        evidence = {s: profile[s] for s in offer["matched"] if s in profile}
        prompt = PROMPT_TEMPLATE.format(
            title=offer["title"], company=offer["company"] or "cette entreprise",
            responsibilities=", ".join(offer["responsibilities"]),
            matched_skills=", ".join(offer["matched"]),
            evidence=json.dumps(evidence, ensure_ascii=False),
        )
        print(f"  Drafting for: {offer['title']} @ {offer['company']}...")
        paragraph = call_ollama(prompt)
        out_path = f"output/cv_drafts/offer_{offer['id']}.txt"
        with open(out_path, "w") as f:
            f.write(f"Offer: {offer['title']} @ {offer['company']}\n\n{paragraph}\n")
        print(f"    -> {out_path}")

    print("\nReminder: output/cv_drafts/ is gitignored -- these are personal drafts, "
```
